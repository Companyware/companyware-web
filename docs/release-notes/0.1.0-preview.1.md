# Companyware Web 0.1.0-preview.1

Status: **Internal release candidate — not tagged or published**

## Scope

- Symfony 6.4 LTS application targeting PHP 8.3.
- Public PHP API 1.0, HTTP API and Administration SDK 1.0.
- Composer-compatible plugin packages with validation, migrations and lifecycle.
- Roles, scoped permissions, audit, recovery and signed extension metadata.
- Documents reference plugin and plugin developer tooling.
- Visible Companyware Web identity while Companyware remains the product family.

## Compatibility

- PHP: `~8.3.0` with the extensions declared in `composer.json`.
- Symfony: `6.4.*`.
- Public PHP API: `1.0`.
- Administration SDK: `1.0`.
- Database: MySQL or MariaDB through the documented migration workflow.

Companyware Desktop is released independently. Desktop plugins and Web plugins
do not share binaries, database tables or release status; integration uses
separately versioned HTTP contracts.

## Security and integrity

The candidate gate includes strict Composer metadata validation, an audit of the
locked dependencies, license and public-API checks, generated-plugin source-header
checks, the PHP reference suite and Administration SDK tests. The final evidence
must identify the exact clean commit, archive SHA-256 and this file's SHA-256.

No credentials, environment files, database exports, caches or publisher private
keys belong in the archive.

## Known limitations and open gates

- This file describes a candidate only; no public supported version exists yet.
- Final local gate output must be recorded for the exact release commit.
- Production deployment, migration, recovery and restricted-authorization checks
  require explicit operator execution and observed results.
- Website, downloads and public documentation must reference the same immutable
  version, artifact and checksums before publication.
- Public remote configuration, repository settings, tag creation and release
  publication require separate authorization.
- The remaining repository and external gates are listed in the
  [GitHub publication checklist](../github-publication-checklist.md).

## Deployment and recovery

Follow [upgrade and recovery](../upgrade-and-recovery.md) and the
[framework release process](../releasing-framework.md). Local checks do not count
as production verification.
